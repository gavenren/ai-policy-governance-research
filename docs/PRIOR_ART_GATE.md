# Working notes: prior-art and implementation gate

**Status:** research working notes; not a finished paper. **Evidence cutoff:** 2026-10-09, with retrieval timestamps in the source manifest. **Review state:** AI-assisted source inspection, including a separately delegated literature search; no human or practitioner review, converter execution, or universal novelty assessment. No legal compliance conclusion follows from these notes.

## Gate decision

**Conditional GO for a bounded, application-specific conformance/counterexample suite. NO-GO for a general claim that reporting-schema conversion inherently loses information, or that decision-relevant preservation benchmarks are new.** A faithful all-preserved result is a valid outcome. The study must name each collection profile, implementation revision, output artifact, and permitted query interface.

The plausible contribution is a reproducible suite of minimal pairs testing a small, declared family of response-workflow queries across authentic AI-report exports. Synthetic records must satisfy the actual source validation rules. A restricted query failure is not evidence of transport loss when the raw record remains available. Crosswalks, explicit missingness, provenance, round-trip laws, and preservation of detection-relevant information all have precedents below.

## Pre-outcome requirements

1. Pin native schemas and actual converters where available. Label any adapter we write as a research implementation and tie every mapping to documented semantics. A paper illustration is not the production schema.
2. Define six bounded workflow questions before outcomes: system/version, observed versus potential harm, negative versus uninvestigated impact, distinct incident/discovery/notification times, containment state, and escalation owner when supplied. These are research rules, not inferred legal duties or a validated practitioner utility model.
3. Separate collection adequacy from translation preservation. A fact never collected cannot be lost in translation. A minimum-valid form and a fully populated supported form answer different questions.
4. Compare documented native outputs, narrative/raw-preserving outputs, and any typed research extension. Include an identity/raw baseline. A typed extension's advantage may be accessibility to a fixed query interface rather than additional transported information.
5. Require valid paired records differing in one declared fact; preserve missing, unknown, explicit negative, disputed, and revised states only where authentic inputs can represent them. Record cases that cannot be expressed without prose or extension.
6. Report exact query answers, normalized output comparisons, validation, and reconstruction results. Test totals count configurations, never incident prevalence. Do not attach causal operational-improvement claims to formal cases.
7. Keep all counterexamples and negative findings. If ordinary native fields or supported extensions eliminate a suspected failure, revise or reject that failure claim. Independent critical review must inspect the actual mapping and results before a complete-study draft is published.
